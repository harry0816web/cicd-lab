### 1.2 Pipeline 設計重點

- 觸發條件：`push`（所有分支）與 `pull_request`
- 執行環境：GitHub-hosted runner `ubuntu-latest`，Node.js 版本 `22`
- 安裝依賴：使用 `npm ci` 確保 lockfile 可重現
- 檢查項目（任一失敗即 pipeline 失敗）：
  - TypeScript typecheck：`npm run typecheck`
  - Prettier check：`npm run format:check`
  - Test：`npm test`（Vitest）
- 測試結果輸出與顯示：
  - 產生 JUnit XML：`reports/vitest-junit.xml`
  - 上傳 artifact：`test-report`（即 `reports/` 目錄）
  - 在 GitHub Actions UI 顯示測試摘要：使用 `dorny/test-reporter` 讀取 JUnit XML

### 1.3 `.github/workflows/ci_112550097.yaml` 主要內容（請擇要貼上）

> 建議直接貼下面這段（已擇要），可確保你報告內容跟實作一致。

```yaml
name: CI 112550097

on:
  push:
    branches:
      - '**'
  pull_request:

permissions:
  contents: read
  checks: write

jobs:
  ci:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: npm
      - run: npm ci
      - run: npm run typecheck
      - run: npm run format:check
      - run: |
          mkdir -p reports
          npm test -- --reporter=default --reporter=junit --outputFile.junit=reports/vitest-junit.xml
      - if: always() && hashFiles('reports/vitest-junit.xml') != ''
        uses: actions/upload-artifact@v4
        with:
          name: test-report
          path: reports/
      - if: always() && hashFiles('reports/vitest-junit.xml') != ''
        uses: dorny/test-reporter@v1
        with:
          name: Vitest (JUnit)
          path: reports/vitest-junit.xml
          reporter: java-junit
```
